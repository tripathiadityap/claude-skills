# Fill the designer's calendar

Load `creator-profile` and `instagram-threads` first. The profile holds the IDs of the designer's calendar, the notes database and any knowledge hub, plus the standard caption footer.

## Steps every run

1. **Read all the notes first, not a sample.** Page through the whole notes data source, newest edits first. Read new and recently edited notes, including saved posts, scripts, episode notes and linked resources. Note what is new since the last run.
2. **Read the calendar rows** (name, date, tags, created time) and fetch the ones in the target range.
3. **Use the existing slots only.** Never create new rows unless the creator says so. Fill slots whose names mark them as open (for example "Business Carousel", "Technology Carousel"). Leave other series alone unless asked.
4. **Match each slot to its pillar by name** and set its tag. Add content to the slot page body. Keep the slot's name and date. If a slot's content is already approved, update it in place.
5. **Pick topics from what the notes actually hold:** saved posts, terms, case studies, episode lessons. Don't repeat a topic already used in the calendar. Prefer ideas the creator saved, then add fresh evergreen topics.
6. **Later changes edit the same page in place.** Log anything new in the notes database and link back to the calendar entry.
7. **Last step:** re-fetch each changed page and check dates, tags and footer.

## What each entry contains

Account, format (carousel 4:5, 7 to 9 slides), goal (saves and sends), three hook options, a slide-by-slide outline (on-image text plus a visual note), caption opener, the standard footer from the profile, and a line saying what is made up or simplified. The designer designs, the creator approves, so slide text is a brief, not final art.

## Voice and angle

- Explain every term with a plain analogy or a tiny made-up example so non-specialists can follow every slide.
- Hooks can be bold and curious but must be true and paid off inside the carousel.
- Alternate pillars (for example Business and Technology).
- Slide 1 is a promise with an open loop. One idea per slide, readable in two seconds. Last slide: save, plus a specific send line ("send this to the friend who..."). No "comment YES" bait.

## Hard rules

- Never invent the creator's facts, numbers or stories. Worked examples use made-up numbers labelled EXAMPLE.
- No credits or sources in captions; put them in the page notes.
- Draft only. Mark entries "Draft, not posted".
- Legal, tax, security and money topics are general information, not advice, and say so on the last slide.

## Reply format

One short summary: which slots were filled (date, pillar, topic), what changed, and any placeholders the creator must fill.
